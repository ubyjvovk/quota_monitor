# Stress review — codex — 2026-08-31
## Summary

The repository is not release-ready: the required baseline failed in the Codex app-server lifecycle test, and several user-visible correctness and credential-handling defects remain. The highest-risk paths can overwrite a damaged config, expose a DeepInfra key in process arguments, discard an otherwise valid DeepInfra-only snapshot, and time out the app while the core is still performing its documented Kimi refresh. DeepInfra parsing also converts missing money fields into authoritative zeroes, violating the project's central absence-is-not-zero rule. Frontends drift on credits, ordering, saved setup state, and credits-only providers, while the local build and signed-release checksum paths can report success for stale or unverifiable artifacts. Live endpoints, an Omarchy shell, Xcode app builds, and signing/notarization were not available to this offline report-only review.

## Findings

### F1 — Setup overwrites a damaged config
- file: core/cmd/quotamon/setup.go:29
- severity: high   confidence: certain
- claim: Any config load error, not just a missing file, makes setup replace the user's existing config with defaults.
- scenario: A config containing a DeepInfra key becomes malformed or temporarily unreadable; `quotamon setup` continues as first-run setup and `Save` overwrites the file, losing the key and provider choices.
- fix: Fall back only for `config.ErrMissing`; report every other load error and leave the file untouched.

### F2 — The GUI exposes API keys in process arguments
- file: App/QuotamonSetup.swift:77
- severity: high   confidence: certain
- claim: The setup UI passes the complete DeepInfra API key as `--api-key=<value>` in the `quotamon` argv.
- scenario: Saving a DeepInfra key makes it visible to process inspection and potentially crash/process diagnostics while the child is running, despite the UI claiming the key is handed straight through without another exposure.
- fix: Add a stdin or inherited-file-descriptor secret input to `quotamon config set` and pass only a non-secret selector in argv.

### F3 — The app kills a core refresh before the core's own budget expires
- file: QuotaKit/Sources/QuotaKit/Engine/QuotamonRunner.swift:114
- severity: high   confidence: certain
- claim: The app enforces a 15-second wall-clock cap even though the core reserves 25 seconds for Kimi prefetch before its separate fetch budget.
- scenario: An expired Kimi token with no eligible cache takes more than 15 seconds to launch/exit the TUI; the app terminates `quotamon`, reports a timeout, and never accepts the otherwise valid provider snapshot.
- fix: Make the runner timeout exceed the core's total prefetch-plus-fetch bound, or pass one shared deadline through to the core and its children.

### F4 — Missing DeepInfra money becomes a live `$0.00` reading
- file: core/internal/providers/deepinfra/sources.go:131
- severity: high   confidence: certain
- claim: `spentUSD` and checklist balance fields default to numeric zero when required response fields are absent or malformed.
- scenario: Endpoint drift returns `{"months":[{}]}` and `{}` from checklist; QuotaMon emits an `ok` live provider with `$0.00 this month` and `$0.00` balance instead of reporting malformed/unknown data.
- fix: Require valid `total_cost` and required checklist money fields before constructing those readings; degrade each missing component to an explicit unknown status.

### F5 — A valid credits-only snapshot exits as failure
- file: core/cmd/quotamon/main.go:341
- severity: high   confidence: certain
- claim: Table and snapshot commands return success only when some provider has a window, ignoring usable credits/spend readings.
- scenario: DeepInfra is the only enabled provider and has no spending limit, so the command prints its valid prepaid balance and monthly spend but exits 1; `QuotamonRunner` then discards stdout and the app keeps stale/empty data.
- fix: Base exit success on the same usability predicate as hybrid resolution: a current window or a credits payload.

### F6 — Kimi refresh violates the recorded no-launch provider policy
- file: core/internal/registry/registry.go:126
- severity: medium   confidence: certain
- claim: The registry automatically wires a Kimi CLI launcher even though `PROVIDERS.md` records the user decision that quotamon must not run the Kimi CLI.
- scenario: A stale Kimi token with an old cache, or any `--fresh` request, invokes an interactive TUI in a pseudo-terminal from a background menu/widget refresh.
- fix: Remove the automatic refresher unless the policy is explicitly reversed and documented, or gate it behind an opt-in config value defaulting off.

### F7 — Reopening Settings forgets saved provider choices
- file: App/SetupView.swift:140
- severity: medium   confidence: certain
- claim: The app initializes every toggle from current credential discovery rather than the saved enabled state.
- scenario: A user manually enabled Codex at an unusual path that discovery misses; opening Settings and pressing Save without editing anything sends `--enabled=false` and silently disables it.
- fix: Load `quotamon config get --json`, merge saved enabled flags with discovery details, and render/save that state.

### F8 — Small and medium widgets hide credits-only providers
- file: QuotaKit/Sources/QuotaKit/UI/ConsoleWidgetView.swift:54
- severity: medium   confidence: certain
- claim: Condensed widget layouts drop every provider without a current quota window even when it has a valid credits/spend reading.
- scenario: A current DeepInfra prepaid balance is present in the shared snapshot, but the small/medium widget omits its row; if it is the only provider, the widget says to open the app to load usage.
- fix: Add a condensed credits row for windowless usable providers instead of filtering solely through `tightestWindow`.

### F9 — Local builds can launch a stale app after compilation fails
- file: scripts/build.sh:27
- severity: medium   confidence: certain
- claim: The `xcodebuild | grep ... || true` pipeline masks the compiler's exit status, and the script accepts any pre-existing app bundle as success.
- scenario: A source edit breaks compilation after one successful build; running `scripts/build.sh` finds yesterday's app in `build/`, launches it, and reports no failed build.
- fix: Preserve `xcodebuild`'s status with `PIPESTATUS` (or an unmasked log pipeline) and remove/uniquely stage the expected product before building.

### F10 — Signed releases publish a self-invalidating checksum file
- file: .github/workflows/release.yml:110
- severity: medium   confidence: certain
- claim: The post-notarization checksum glob includes the existing `SHA256SUMS` while the shell simultaneously truncates and rewrites it.
- scenario: In a signed release, the generated file contains the hash of an empty `SHA256SUMS`, then grows to include that line; `shasum -c SHA256SUMS` fails on its own entry.
- fix: Exclude `SHA256SUMS` from the input list, write to a temporary file, and atomically rename it.

### F11 — The frozen Swift Codex live route still uses the known-bad identity and shape
- file: QuotaKit/Sources/QuotaKit/Providers/CodexSources.swift:247
- severity: medium   confidence: certain
- claim: The Swift live source sends the spoofed `codex_cli_rs` headers recorded as a likely 403 trigger and does not normalize the documented `wham/usage` `rate_limit.primary_window` shape.
- scenario: A user points `QUOTA_MONITOR_CODEX_USAGE_URL` at the working wham endpoint; the request can be rejected because of its headers, and a successful wham body is still reported malformed.
- fix: Port the Go HTTP source's honest headers and explicit wham-shape conversion into the frozen reference bug-fix path.

### F12 — Omarchy has no watchdog for a stuck fetch process
- file: omarchy/Panel.qml:122
- severity: medium   confidence: likely
- claim: The QML process lifecycle has no timeout or cancellation timer, so UI recovery depends entirely on `quotamon` exiting.
- scenario: A child cleanup or provider process ignores its context; `fetchProc.running` stays true forever, the Refresh button remains disabled, and future timer/manual refreshes only queue or return.
- fix: Add a watchdog that terminates then kills the process, clears `refreshing`, and reports a timeout while retaining the last good snapshot.

### F13 — Waybar drops credits for providers that also have windows
- file: core/cmd/quotamon/waybar.go:80
- severity: medium   confidence: certain
- claim: The tooltip renders credit rows only when `len(provider.Windows) == 0`, unlike the console table which always renders reported credits.
- scenario: Claude reports quota windows plus a prepaid balance or disabled extra-usage balance; the console/macOS panel show it, while Waybar's tooltip omits it entirely.
- fix: Append shared `creditLines` whenever credits exist, regardless of window count.

### F14 — Waybar window order disagrees with the console table
- file: core/cmd/quotamon/waybar.go:65
- severity: low   confidence: certain
- claim: The tooltip iterates raw provider windows rather than the `SortedWindows` order used by the console and macOS panel.
- scenario: A later weekly window is at 90% while the first session window is at 10%; the console puts the weekly limit first, but Waybar puts it second.
- fix: Iterate `provider.SortedWindows(now)` in the tooltip.

### F15 — Rolled-over windows are persisted as fabricated zero samples
- file: QuotaKit/Sources/QuotaKit/Engine/UsageHistory.swift:41
- severity: low   confidence: certain
- claim: Usage history records `effectiveUsedPercent`, which converts an expired reading into zero instead of omitting it.
- scenario: Auto-refresh runs after a cached window resets; history appends a 0% point and creates a false cliff even though the current reading is unknown.
- fix: Record only `currentUsedPercent` values and skip windows whose reading is nil.

## What I could not verify

- The ticket prohibited network access, so I did not probe any live provider endpoint or validate current vendor response drift.
- I did not read real credentials, Keychain data, home-directory state, or API keys; credential findings are derived from explicit code paths only.
- This lane did not run `xcodebuild`, an Omarchy/Quickshell runtime, codesigning, notarization, or a signed release, so those findings are static lifecycle/shell analyses.
- The required one-time baseline run failed; I did not rerun it because the ticket explicitly required one run first. I therefore could not determine whether the Codex app-server timeout is deterministic or load-sensitive.
- `PROVIDERS.md` says quotamon must not launch Kimi, while `core/README.md` documents the opposite behavior; I treated the provider contract as authoritative because `AGENTS.md` explicitly says every rule in it applies to the Go port.
