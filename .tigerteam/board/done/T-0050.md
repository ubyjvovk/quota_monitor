## Design — implement exactly this
- `http.go` `whamWindow`: emit the reset under `resets_at` so `codex.Window`
  actually reads it; the wham test asserts `ResetsAt != nil` with the fixture
  value.
- `local.go`: a per-file `LastLine` error is recorded and SKIPPED (continue to
  the next rollout), not returned as a source-wide Transport error. When the
  last line containing `rate_limits` in a file is not a payload.rate_limits
  record, keep scanning BACKWARDS within the same file for earlier candidate
  lines before moving on (make LastLine return candidates lazily or add a
  bounded reverse scan — your call, documented). Tests: one unreadable file
  among good ones still yields a reading; a file whose tail line merely quotes
  "rate_limits" in chat text still yields the earlier real record.
- Deflake `TestRunAppServerKeepsStdinOpenUntilRateLimitsReply`: it timed out
  at its 3 s budget while four workers saturated the host (10/10 green quiet).
  Isolate + poll: derive the deadline from a generous constant (>=15 s) with
  the test polling for completion, never weaken the assertion.

### Design choices
- **Bounded reverse scan, lazily.** `eachCandidate` offers at most
  `defaultMaxCandidates` (32) matching lines per pass, newest first, and stops at
  the first one the caller keeps. The tail is still read first as a fast path; the
  whole file is re-read only when every tail candidate is rejected, so a decoy that
  lives inside the tail cannot hide a real record that sits before it.
- **Skipped read errors are not swallowed.** The first one is kept and, if no
  rollout at all yields a reading, reported as the source-wide `Transport` error
  instead of the vaguer `NoDataFound` — a permissions problem still surfaces.
- **App-server budget.** `appServerReplyBudget = 30s` (ticket asked for >= 15s).
  `runAppServer` runs in a goroutine and the test waits on a channel, failing hard
  if nothing arrives 5s past the budget. The assertion is unchanged in strength:
  the run must complete *before* the context deadline, i.e. because of the id:2
  reply and not because the context expired.
