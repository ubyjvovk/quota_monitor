## Goal
DeepInfra's endpoints answer in 2–7 s and occasionally more; with the CLI's
10 s overall budget and an 8 s per-call cap it intermittently reports
"slow to answer" even though a fresh reading was one second away. Give the
fetch stage a 15 s default budget, make it tunable, and lift DeepInfra's
per-call cap to 12 s.

## Context
- Budget lives in `core/cmd/quotamon/main.go` (10 s fetch context; after
  T-0025 a separate 25 s pre-fetch stage exists — leave that alone).
- DeepInfra `CallTimeout` default in `providers/deepinfra/sources.go` (T-0023).
- Waybar calls every 300 s, so a 15 s worst case is harmless.

## Design — implement exactly this
- `--timeout <seconds>` global flag (also `QUOTA_MONITOR_TIMEOUT` env,
  flag wins), default 15, must be any finite positive number (fractions
  allowed; reject `<= 0`, non-numeric, NaN/Inf with usage, exit 2), applies
  to the fetch stage of the table, `--json`/`snapshot`, `waybar`, and `check`.
- DeepInfra `CallTimeout` default 12 s.
- The "slow to answer" message states the actual cap (`>12 s`).
- While in `deepinfra.go`: compare `remaining` in whole cents (`math.Round(x*100)`) so `-8.0 − 7.97` is `3` cents (prepaid) and `-8.0 − 8.0` is exactly zero, never a float artefact; add both cases to the mapping test.

## Questions

The design says `--timeout` has a minimum of 1 second, but the acceptance test
requires `--timeout 0.2` to be valid, cancel a one-second source, report it
unavailable, and finish in under one second. Rejecting or clamping `0.2` obeys
the design but makes that acceptance criterion impossible.

Options:
1. Accept any finite timeout greater than zero (recommended). This preserves
   the exact `0.2` acceptance test while keeping the production default at 15
   seconds; revise “minimum 1” to “must be greater than 0”.
2. Keep the one-second minimum and revise the acceptance test to use a valid
   value (for example `--timeout 1` with a two-second stub and a suitably
   bounded elapsed-time assertion). This changes the explicit test and makes
   it slower.

Please choose which public validation rule governs the flag. No CLI parsing,
fetch-budget wiring, related tests, or `core/README.md` timeout documentation
were added because doing so would guess that decision.

## Answers

PM answer: option 1 — my "minimum 1" was wrong. The rule is **timeout must be
> 0** (any finite positive number of seconds; fractional allowed). Keep the
default 15 and the `0.2` acceptance test as written. Reject only `<= 0`,
non-numeric, or NaN/Inf → usage, exit 2. Update the design line accordingly
and hand off to review.
