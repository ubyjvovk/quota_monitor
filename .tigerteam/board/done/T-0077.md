## Goal
`versionWarning` tells the user to "use the Update button below" while
`coreUpdateVersion` returns `""`, so no button is rendered. The advice points at
something that is not there — the same dead end T-0075 was filed to remove,
relocated to older cores.

Reproduced against the shipped manifest (2026.9.2) with a snapshot carrying no
`version` key:

```
button : (none)
warning: quotamon is older than this plugin needs (2026.9.1) — use the Update button below
```

The Install button does not cover this either: it is
`visible: root.rows.length === 0`, and a pre-2026.9.1 core still returns
readings, so the panel has rows and hides it.

This is a spec error in T-0077's predecessor, not a worker mistake. T-0075 said
"an unknown core version must **not** produce an update offer here; that case is
what `versionWarning` is for". That reasoning was wrong: a core too old to
report a version is exactly a core that should be updated, and the warning it
falls through to has no button to point at.

## Context
- The snapshot's top-level `version` key was added by T-0064 and first shipped
  in **2026.9.1**. So an absent `version` on an otherwise working snapshot means
  the core predates 2026.9.1 — old by definition, and older than any manifest
  this plugin will ever carry.
- `Model.coreVersion(snapshot)` returns `""` both when the snapshot is
  `null`/`undefined` and when it is a real snapshot without a `version` key.
  **Those two cases must not be treated the same.** No snapshot at all is the
  Install button's territory; a real snapshot without a version is this ticket's.
- `coreUpdateVersion` currently reads:

```js
function coreUpdateVersion(manifest, snapshot) {
  var version = pinnedVersion(manifest)
  var core = coreVersion(snapshot)
  if (version === "" || core === "") return ""
  var comparison = compareVersions(core, version)
  return comparison !== null && comparison < 0 ? version : ""
}
```

- The panel is unchanged by this ticket: it already binds
  `visible:` and its label to `coreUpdateVersion`, so fixing the function is
  enough. Do not edit `Panel.qml`.

## Design (decided; implement exactly this)

`coreUpdateVersion(manifest, snapshot)` returns `pinnedVersion(manifest)` when
the manifest pin is valid **and** any of:

1. the core version parses and compares lower than the pin (today's behaviour); or
2. the core version is absent **while `snapshot` is a non-null object** — an
   old core that reports readings but no version.

It returns `""` when:

- the manifest pin is invalid or missing;
- `snapshot` is `null` or `undefined` (nothing is installed or nothing ran —
  the Install button's job, not this one);
- the core version parses and is equal to or newer than the pin;
- the core version is present but unparseable, e.g. `"dev"` — a developer build
  must never be nagged to overwrite itself. **Keep this case returning `""`;**
  it is the one place where "cannot compare" must stay silent, because a `dev`
  core is deliberate rather than stale.

Note the asymmetry and comment it: an **absent** version means an old release,
an **unparseable** version means a local build. They are not the same and must
not collapse into one branch.

`versionWarning` is unchanged — when both fire, the user correctly sees a red
"too old to work" line *and* a button that fixes it.
