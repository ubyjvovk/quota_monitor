## Design — implement exactly this
- `grok.go` Snapshot: `Label: snapshot.LabelFromMinutes(windowMinutes)` and
  `Kind: snapshot.KindFromMinutes(windowMinutes)` when the period bounds are
  known; keep the literal "Week"/KindWeekly ONLY as the fallback when they are
  not. Test: a 30-day period fixture renders a monthly label/kind; the weekly
  fixture stays "Week".
- `discover.go`: exec `/usr/bin/security` absolutely (mirror the comment in
  claude.go about why); sort Grok credential scope keys before selecting one
  so the reported expiry is deterministic. Tests: scope selection stable
  across map orders (two scopes, assert the chosen one).

## Worker report

### Files changed (and why)
- `core/internal/providers/grok/grok.go` — Snapshot now derives the window
  `Label`/`Kind` from the provider-reported period duration via
  `snapshot.LabelFromMinutes`/`KindFromMinutes` when the period bounds (start
  + end) are known, so a monthly period renders "30d"/monthly instead of a
  misleading "Week". The literal `Week`/`KindWeekly` is retained as the
  fallback only when no period bounds are known (e.g. the
  `USAGE_PERIOD_TYPE_WEEKLY`-only and no-bounds cases).
- `core/internal/providers/grok/grok_test.go` — new test
  `TestSnapshotRendersAMonthlyLabelAndKindForAThirtyDayPeriod` asserting a
  30-day period yields "30d"/`KindMonthly` and 43 200 window minutes. The
  existing `assertFixtureWindow` already pins the weekly fixture to "Week".
- `core/internal/discover/discover.go` — `discoverClaude` now execs
  `/usr/bin/security` by absolute path (with a comment mirroring the Claude
  provider) so a hostile PATH entry can't substitute a fake CLI.
  `discoverGrok` now sorts scope keys before selecting one, so the reported
  expiry is deterministic across map iteration orders (matching
  `ParseCredentials`).
- `core/internal/discover/discover_test.go` — updated the stubbed security
  assertion to expect `/usr/bin/security`; new test
  `TestGrokDiscoverySelectsAScopeDeterministicallyAcrossMapOrders` feeding two
  scopes in both JSON orders and asserting the same (first-sorted) scope's
  expiry is always reported.
