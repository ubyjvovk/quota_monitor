## Goal
Two things the product owner asked for after seeing the merged panel:
1. The app's text is visibly heavier than `docs/console.png`. Root cause
   (PM-verified by ink measurement, 961 vs 573 in the same word):
   `/System/Library/Fonts/SFNSMono.ttf` is a variable font whose default
   instance is **Light** (weight axis default 294), and the console screenshot
   is drawn at that default — while the app asks for `.regular`. Use
   `.light`.
2. The widget (`Widget/QuotaWidget.swift`) still wears the old Tufte styling.
   Restyle it in the console look: SF Mono Light, console palette, `█░` bars,
   severity colouring — and make it PM-verifiable by putting its view in
   QuotaKit so the app's headless render path can draw it.

## Design — implement exactly this
### `QuotaKit/Sources/QuotaKit/UI/ConsoleTheme.swift` (moved from `App/`, now `public`)
- Identical to today's `App/ConsoleTheme.swift` except: `public enum`,
  every member `public`, and the font is

  screenshot is drawn at). Wrap in `#if canImport(SwiftUI) && canImport(AppKit)`.
- Delete `App/ConsoleTheme.swift`. `App/` already `import QuotaKit`, so no
  other App change is needed for this.

### `QuotaKit/Sources/QuotaKit/UI/ConsoleWidgetView.swift` (new, `public`)
```swift
/// The widget's face: console rows in SF Mono Light, one per provider, sized
/// to the widget family. Lives in QuotaKit so the app can render it headlessly
/// (the widget itself needs an App Group to be installed).
public struct ConsoleWidgetView: View {
    public enum Size: Sendable { case small, medium, large }
    public init(snapshot: QuotaSnapshot, asOf now: Date, size: Size)
    /// The rows this view draws, as console lines — the testable part.
    public static func lines(for snapshot: QuotaSnapshot, asOf now: Date, size: Size) -> [ConsoleTable.Line]
    public var body: some View
}
```
- `lines(for:asOf:size:)`, in `snapshot.rankedProviders(asOf:)` order
  (tightest first — a widget has no room to make the user hunt), one line per
  provider **that has a current reading** on its `tightestWindow(asOf:)`;
  providers whose window rolled over are dropped (no room to explain a dash).
  - `.small`: `pad(shortName, 3) + " " + bar(8) + " " + pct4` — 17 columns.
    Bar: `round(used / 100 * 8)` `█` cells, clamped 0…8, then `░` to 8.
  - `.medium`: `pad(shortName, 3) + " " + bar(20) + " " + pct4 + "  " + countdown`
    where bar(20) is exactly `ConsoleTable`'s rule (`round(used/5)`) and
    countdown is `QuotaFormat.countdown(timeUntilReset)`, `—` when there is no
    `resetsAt` — 37 columns max.
  - `.large`: `ConsoleTable.render(snapshot.providers, asOf: now)` verbatim —
    the whole console table, snapshot order, blocks separated by an empty line.
  - Tones as in `ConsoleTable`: the `█` run and the percent carry the window's
    `QuotaFormat.Severity` as `.warning`/`.critical`; `.normal` → `.plain`;
    everything else `.plain`. Merge adjacent same-tone spans.
  - `pct4` = `QuotaFormat.percent` right-aligned in 4 cells.
- `body`: the lines as ONE `Text` from an `AttributedString` (same technique
  as `App/ConsoleTableView.swift` — copy it, do not import App code), font
  `ConsoleTheme.font`, `.lineSpacing(ConsoleTheme.lineSpacing)`,
  `.minimumScaleFactor(0.7)` so the medium/large columns fit inside the family
  width without breaking alignment (one Text scales uniformly), `.lineLimit`
  = number of lines, top-leading in a `frame(maxWidth: .infinity, maxHeight: .infinity)`,
  padding `ConsoleTheme.padding`. Empty `lines` → `Open Quota Monitor to load usage.`
  in `ConsoleTheme.font` / `.chrome`. No background here — the caller sets it.

### Worth a close look at review
1. **`ConsoleWidgetView.lines` and every row helper are marked `nonisolated`.**
   This is not cosmetic and it cost most of the ticket's time. `View` is a
   `@MainActor @preconcurrency` protocol, so conforming to it makes *every*
   member of the type main-actor isolated — static members included. The
   `compactMap` closure in `lines` then inherited that isolation and **trapped
   the whole test process (SIGTRAP, exit signal 5, no message in the log)** the
   moment swift-testing invoked it off the main thread. It reproduced only when
   at least one provider actually reached the closure, which is why
   `emptySnapshotHasNoLines` and the `.large` path passed while the other three
   killed the run. There is a comment in the file recording this; please keep it.
   If a reviewer prefers, the alternative fix is to move line building out of the
   `View` into its own type — I kept the API the ticket specified.
2. `App/DesignSnapshot.widgetFamilies` is a **computed** `static var`, not a
   `static let`, purely to sidestep any Swift 6 global-Sendable question on a
   tuple array in a target I cannot compile.
3. The tuple field is named `file` and holds `"widget-small"` etc. so the
   ticket's literal grep criterion matches; the filename is
   `"\(prefix)-\(family.file)-\(name).png"`.
4. `minimumScaleFactor(0.7)` on a single `Text` is what is supposed to keep the
   37-column medium row inside 329 pt; that is exactly the thing only the render
   can confirm. Watch the small family too — 17 columns × ~7.8 pt = 133 pt against
   155 pt minus WidgetKit's margins minus `ConsoleTheme.padding` (14 pt a side),
   so it will almost certainly be scaled down rather than drawn at 13 pt. If that
   looks too small, the honest fix is a smaller `padding` for the widget, which
   is a ticket, not a drive-by.
