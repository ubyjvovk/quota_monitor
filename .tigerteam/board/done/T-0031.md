## Design — implement exactly this
### Binary bundling
- `project.yml`: add a build phase (or a pre-action script) to the app target
  that runs `make -C core matrix` and copies a **universal** `quotamon` into
  the app's Resources: `lipo -create core/bin/quotamon-darwin-arm64 <amd64> -output` —
  amd64 may be absent on some hosts, so fall back to copying the arm64 binary
  directly when `lipo` has one slice. Put it at `Contents/Resources/quotamon`.
  `scripts/build.sh` stays the one-command build (xcodegen generate + xcodebuild),
  and must succeed producing the .app with the binary embedded.
- The app resolves it via `Bundle.main.url(forResource: "quotamon", withExtension: nil)`
  and constructs `QuotamonRunner.bundled(executableURL:)`. The app is
  unsandboxed (entitlements already allow this); the widget never execs.

### Menu-bar app (`App/`)
- `QuotaMonitorApp`: `MenuBarExtra` (`.window` style). Label = `QuotaFormat.menuBarTitle(for: engine.snapshot)`. Build the engine with the bundled runner:
  `QuotaEngine(runner: .bundled(executableURL: <resolved>))`. Start
  `engine.startAutoRefresh()` in a `.task`.
- Panel content = **console-style table**, simple (drop sparklines/pace):
  one section per provider in `engine.snapshot.rankedProviders(asOf:)` order:
  header line `DisplayName · plan · origin · age`; then one row per
  `sortedWindows`: `label`, a thin bar (a `Capsule`/`ProgressView`-style fill
  proportional to usedPercent, coloured by `QuotaFormat.Severity.forUsage`),
  `percent` (or `—` when `currentUsedPercent(asOf:)` is nil), and the reset
  countdown; then credits/spend lines when present (same rules as the console:
  disabled-zero omitted, `$X remaining`, `$X this month`).
- Footer: a **Refresh** button → `Task { await engine.refresh(fresh: true) }`,
  disabled while `engine.isRefreshing`; show `engine.lastError` as a small
  warning line when non-nil; a "Quit" item; a gear that reopens setup.
- First-run: on appear, if `engine.snapshot.providers.isEmpty` AND
  `quotamon config path` file is absent (or the runner threw notConfigured),
  show `SetupView` instead of the table.

### First-run `SetupView`
- Runs `quotamon discover --json`, lists each provider row (found/✓, not/✗,
  unsupported/·, with the `detail`), a `Toggle` per supported provider
  (default on when found), and a `SecureField` for providers with `needsKey`
  (DeepInfra). "Save" writes via `quotamon config set <id> --enabled=<bool>
  [--api-key=<v>]` per provider, then triggers `engine.refresh(fresh: true)`
  and dismisses. All shelling goes through a small `Setup` helper that uses the
  same bundled `quotamon` URL. Never log the key.

### Widget (`Widget/`)
- Timeline provider reads the shared snapshot via `SnapshotStore` (App Group
  when available, else the placeholder it already shows). Render a compact
  view: the 2–3 tightest providers as `shortName pct%` rows, coloured by
  severity; "Open Quota Monitor" when no readable snapshot (unchanged
  fallback). No exec, no network.

### Screenshot render path
- Keep `App/DesignSnapshot.swift`'s `QUOTA_MONITOR_RENDER` behaviour, adapted
  to the new panel view, rendering `<prefix>-light.png` and `<prefix>-dark.png`
  from **preview/sample data** (never real). This is how the PM captures the
  app screenshot; it must run headlessly (no display) and exit.

### For the reviewer
1. **Nothing here has been compiled.** Treat every SwiftUI file as unreviewed for
   type errors. The blocker is in `## Questions`.
2. **Gap in the cross-language contract, flagged rather than worked around:**
   Go's `snapshot.Credits` has a `Spend *string` field
   (`core/internal/snapshot/snapshot.go:135`) that Swift's `Credits`
   (`QuotaKit/Sources/QuotaKit/Models/ProviderSnapshot.swift:107`) does not
   decode. So the app reproduces every console credit rule *except* the
   two-row case in `creditLines` (`core/cmd/quotamon/table.go:121`) where a
   provider reports a prepaid balance **and** month-to-date spend — DeepInfra
   with a balance. The app shows the balance row and drops the spend row. The
   unlimited-with-balance case (`spend  $7.75 this month`) does render, because
   there the figure travels in `balance`. Fixing this properly means adding
   `spend` to `QuotaKit`'s `Credits`, which is out of scope for this ticket.
3. **`quotamon snapshot` exits 1 when no provider has windows**
   (`windowExitStatus`, `core/cmd/quotamon/main.go:310`), and
   `QuotamonRunner` treats any non-zero exit as a failure. A user configured
   only for credits-only providers (DeepInfra alone) would therefore see the
   app's error line instead of their spend, even though valid JSON was printed.
   Not touched — it is in `core/`/`QuotaKit/`, both out of scope.
4. The first-run check matches `engine.lastError` against the literal
   `"Run first-time setup for quotamon"` that `QuotamonRunner` raises for exit 3
   (`QuotamonRunner.quotaError(for:)`). `QuotaEngine` publishes errors as
   `String`, so there is no typed alternative; the `config path` file check is
   the primary signal and the string is only a fast path.
5. `project.yml`'s build script prepends `/opt/homebrew/bin` and
   `/usr/local/bin` to `PATH` because Xcode's script PATH excludes Homebrew,
   where `go` lives on this machine. If a reviewer's Go is elsewhere the phase
   will fail loudly rather than silently ship a stale binary.
