## Goal
`QuotaKit`'s Claude fetcher (the frozen parity reference behind `quotactl`) has
the same bug T-0037 fixes in Go: it renders `spend.limit − spend.used` (the
monthly extra-usage cap) as a prepaid balance. Bug-fix it to the same reading
so `quotactl --json` and `quotamon --json` agree again.

## Context
- `ClaudeSources.swift`, the `if let spend = limits["spend"]` block building
  `Credits(...)`. `Credits` now carries `spend: String?` (T-0033).
- Real payload: `Tests/QuotaKitTests/Fixtures/claude-usage-live.json` → `spend`
  has `used`/`limit`/`balance` money objects (`amount_minor`, `exponent`,
  `currency`), `enabled`, `disabled_reason`; `balance` is `null` there.
- Existing tests asserting a `"20.00"` balance for that fixture encode the bug —
  rewrite them. Tests are swift-testing; never touch network/Keychain/$HOME.

## Design — implement exactly this (identical semantics to T-0037)
- `money(_ value: JSONValue?) -> String?`: `amount_minor` (number, required),
  `exponent` (default 2), `currency` (default "USD"); format with `exponent`
  decimals; `$` prefix for USD, otherwise `"<amount> <CUR>"`. JSON null → nil.
- `enabled` = `spend.enabled` (default true). `balance` = `money(spend.balance)`.
  `spend` string = `"<used> of <limit> this month"` when both used and limit
  format, `"<used> this month"` when only used does, else nil.
  `hasCredits` = `enabled && balance amount > 0`. `unlimited` = false.
  No `spend` object → `credits = nil`. Never derive balance from limit − used.
