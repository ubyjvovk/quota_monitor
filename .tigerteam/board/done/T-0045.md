## Goal
Fix the exit-code contract (consolidated findings: opus F1, codex F5, ds F3 in
`.tigerteam/reviews/2026-08-31-*.md` — read all three first). A snapshot the
tool itself considers renderable must exit 0; frontends treat non-zero as
"discard stdout", so today a credits-only DeepInfra setup or an all-sources-
down-with-guidance snapshot never reaches the user.

## Design — implement exactly this
- Replace `windowExitStatus` with: exit 0 iff at least one provider has a
  CURRENT window reading (`CurrentUsedPercent` reports one) OR a non-nil
  `Credits`. Otherwise exit 1. Exit 2 (usage) and 3 (no config) unchanged.
- A snapshot whose windows have ALL rolled over and has no credits → exit 1
  (ds F3): existence of a window object is not a reading.
- Usage text: annotate `--fresh` as accepted by table/snapshot/waybar only
  (ds F6) — parseArguments already rejects it elsewhere; make the text honest,
  do not change parsing.
- Update `main_test.go` assertions to the new contract; add cases: credits-only
  → 0; all-rolled-over, no credits → 1; one current window → 0.
