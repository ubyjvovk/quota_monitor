## Goal
T-0025 launches the Kimi TUI under `script(1)` to let it refresh its own
token. If the keystrokes do not land (slow start, changed UI, no pty), that
launch must never leave a `kimi` behind, and repeated `quotamon` runs (Waybar
every 5 min, manual calls) must never accumulate copies. The PM reproduced
the failure mode: killing `script` alone does **not** kill its child `kimi`.

## Context
- `core/internal/providers/kimi/refresh.go` (`CLIRefresher`, T-0025).
- Cache dir: `cache.Store.Dir` (beside `config.json`).

## Design — implement exactly this
- Start the command in its **own process group**
  (`cmd.SysProcAttr = &syscall.SysProcAttr{Setpgid: true}`); on deadline or
  ctx cancel send SIGTERM to `-pgid`, wait 2 s, then SIGKILL `-pgid`, then
  `cmd.Wait()`. Never rely on `/exit` having worked.
- Exclusive lock: `flock(LOCK_EX|LOCK_NB)` on `<cache dir>/kimi-refresh.lock`
  for the duration of a refresh; if the lock is held, return
  `source.Transport("Kimi refresh already in progress")` immediately.
- Pid file `<cache dir>/kimi-refresh.json` = `{"pgid":N,"started":RFC3339}`
  written after Start, removed after Wait. Before launching: if the file exists
  and `kill(-pgid, 0)` succeeds **and** `ps -o command= -g <pgid>` (or reading
  `/proc/<pid>/cmdline` on Linux) contains `script` and our resolved `kimi`
  path → it is ours: SIGKILL the group and remove the file. Never touch a
  `kimi` that is not in a pgid we recorded.
- Rate cap: if `started` in the pid file (or a `kimi-refresh.last` stamp) is
  younger than 10 minutes, do not launch; return
  `source.Transport("Kimi refresh attempted <age> ago — waiting")`.
- Windows: refresher returns NotConfigured("Kimi auto-refresh is not
  supported on Windows — open `kimi` to refresh") — no process handling.
