## Goal
T-0064 created `VERSION` (CalVer `YYYY.M.MICRO`, currently `2026.9.1`) and made
the Go core read it. This ticket makes the other two components — the macOS app
and the Omarchy plugin — carry the same string, replaces the old
`{major}.{commit count}` version arithmetic in the build and release scripts,
and adds a check that fails the test suite the moment the three literals drift
apart. Three files must physically contain the version (the Go binary gets it
via ldflags, but `project.yml` and `omarchy/manifest.json` cannot — the plugin
manifest is published standalone by subtree split and must be literal), so the
only safe design is one writer script plus one consistency check.

## Context
- `VERSION` (repo root) is the single source of truth. Format:
  `YYYY.M.MICRO` — 4-digit year, month with no zero padding (1–12), MICRO =
  the release count within that month starting at 1. `2026.9.1`, `2026.9.2`,
  `2026.10.1`. MICRO is not a day of the month.
- `project.yml` line 21: `MARKETING_VERSION: "0.1.0"` under `settings.base`.
  This is what the macOS About panel shows when nothing overrides it.
- `omarchy/manifest.json` line 5: `"version": "1.0.0"`. **Careful:** the file
  also has `"schemaVersion": 1` on line 2 — a naive `version` match hits both.
  Match the top-level `"version"` key only.
- `scripts/build.sh` lines 26-29 compute `VERSION="${MAJOR}.$(git rev-list --count HEAD)"`
  and pass it as `MARKETING_VERSION` to xcodebuild.
- `scripts/release.sh` computes `TAG="v${MAJOR}.${COUNTS}"` the same way, then
  guards on: master only, clean tree, tag not already present. `--dry-run`
  prints the tag from any branch but still refuses a dirty tree.
- `.github/workflows/release.yml` "Compute version" step derives `VERSION` from
  the pushed tag (`${GITHUB_REF_NAME#v}`), falling back to `0.0.0-dev` for a
  `workflow_dispatch` run. That fallback is now wrong — a dispatch run should
  build the VERSION file's version.
- `scripts/test-all.sh` is the single test entry point (tigerteam `test_cmd`).
  It runs suites in sequence, each `|| rc=1`, and prints `### <name>` headers.
- `scripts/package.sh` takes the version as `$2` from its caller; it needs no
  change.

## Design (decided — implement exactly this, do not redesign)
1. **`scripts/set-version.sh <calver>`** — the only writer.
   - Validates the argument against `^[0-9]{4}\.(1[0-2]|[1-9])\.[0-9]+$` and
     exits 2 with a usage message naming the scheme if it does not match.
   - Writes `VERSION` (value + newline), rewrites `MARKETING_VERSION: "…"` in
     `project.yml`, and rewrites the **top-level** `"version": "…"` in
     `omarchy/manifest.json`.
   - Prints one line per file showing `old -> new`.
   - Idempotent: running it twice with the same argument is a no-op that still
     exits 0.
   - Fails loudly (non-zero) if any target file is missing or if a rewrite
     produced no change when the value differed — never silently miss a file.
   - Header comment states the CalVer scheme and that this script is the only
     supported way to bump the version.
2. **`scripts/check-versions.sh`** — the reader/verifier. Exits 0 when all
   agree; on failure prints one line per mismatch naming file, expected, and
   found, then exits 1. It checks:
   - `VERSION` exists and matches the CalVer pattern above;
   - `project.yml` `MARKETING_VERSION` equals it;
   - `omarchy/manifest.json` top-level `version` equals it.
   No network, no git, no build — pure file reads, so it is fast enough to run
   in every suite.
3. **`scripts/test-all.sh`** gains a step, before the Swift suite:
   ```
   echo "### version consistency"
   bash scripts/check-versions.sh || rc=1
   ```
4. **`project.yml`**: `MARKETING_VERSION: "2026.9.1"`.
5. **`omarchy/manifest.json`**: `"version": "2026.9.1"`. **Change that one key
   and nothing else in the file** — the rest of the manifest (id, description,
   dependencies, license) is rewritten by T-0067 and a conflicting edit here
   costs a rework.
6. **`scripts/build.sh`**: replace the `MAJOR`/`git rev-list` arithmetic with
   `VERSION="$(cat "$ROOT/VERSION")"`, failing with a clear message if the file
   is missing or empty. Update the comment above it (it currently explains the
   commit-count scheme). Everything else in the script is unchanged.
7. **`scripts/release.sh`**: `TAG="v$(cat VERSION)"`; drop `MAJOR`/`COUNTS`.
   Keep all three existing guards and `--dry-run` exactly as they behave today.
   Add one guard: if the tag already exists, the error message must tell the
   user to bump first — `run scripts/set-version.sh <next version> and commit`.
   Add `--next`, which prints the suggested next CalVer for today (this year,
   this month, MICRO = 1 + the highest MICRO among existing
   `v<year>.<month>.*` tags, or 1 when there are none) and exits without
   touching anything. Update the header comment to describe CalVer.
8. **`.github/workflows/release.yml`**:
   - the `workflow_dispatch` fallback becomes the VERSION file's contents
     instead of `0.0.0-dev` (note the checkout step currently runs *after*
     "Compute version" — reorder so the file is available, keeping the tag
     branch working);
   - add a step, after checkout, that fails the run when a tag build's version
     does not equal the VERSION file: a tag `v2026.9.1` on a tree whose VERSION
     says `2026.9.2` must stop the release with a message naming both.
