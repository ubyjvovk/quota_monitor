## Goal
`scripts/release.sh` reads the version with a bare `cat VERSION`, so it only
works when the caller's current directory happens to be the repo root. Run from
anywhere else it dies with `cat: VERSION: No such file or directory` and exit 1
— including `./scripts/release.sh --dry-run`, which is documented as safe to run
from anywhere. Before T-0065 the script derived its tag from `git rev-list`,
which works from any directory inside a checkout, so this is a regression in the
release path. Fix it the way `scripts/build.sh` already does.

## Context
- `scripts/build.sh` (lines 11-13) is the pattern to copy verbatim:
  ```bash
  ROOT="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"
  cd "$ROOT"
  ```
- `scripts/release.sh` currently has no `ROOT` resolution and no `cd`. The
  offending line is `TAG="v$(cat VERSION)"`.
- The `--next` branch runs `git tag --list` before that line; git commands work
  from any directory in a checkout, so `--next` is not currently broken — but it
  must keep working after the change.
- The script's other guards (master-only, clean tree, tag-does-not-exist) are
  all git-based and unaffected.
- Reproduce the bug: `cd core && bash ../scripts/release.sh --dry-run`.
