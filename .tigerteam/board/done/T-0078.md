## Goal
`QUOTAMON_RELEASE_BASE` takes precedence over the version argument, so the
CalVer pin the panel passes can be silently overridden by an unvalidated
environment variable:

```bash
if [[ -n ${QUOTAMON_RELEASE_BASE:-} ]]; then
  release_base=$QUOTAMON_RELEASE_BASE      # wins over an explicit pin
elif [[ -n $version ]]; then
  release_base="https://github.com/ubyjvovk/quota_monitor/releases/download/v$version"
else
  release_base=https://github.com/ubyjvovk/quota_monitor/releases/latest/download
fi
```

The script then downloads that URL, `chmod +x` es it, and runs it
(`"$bin" providers`). Quickshell's `Process` inherits the compositor session's
environment, so the panel can believe it pinned 2026.9.2 while installing
something else entirely.

Raised by a security review of published plugin commit `7aa3d8e`. The review
also called the download source mutable and the checksum self-delivered; the
first is stale (T-0075 pins the panel path) and the second is real but is a
larger piece of work — see Out of scope.

The realistic failure here is not a sophisticated attacker, who would need code
execution as the user anyway. It is a stale `export QUOTAMON_RELEASE_BASE=...`
left in a shell profile from testing, silently redirecting every future install.

## Context
- The override exists for tests and unusual systems, alongside `QUOTAMON_ARCH`
  and `QUOTAMON_BIN_DIR`. **It must keep working for its intended use** — the
  T-0075 acceptance runs invoked the script with `QUOTAMON_BIN_DIR` set, and a
  future test may point `QUOTAMON_RELEASE_BASE` at a local fixture directory.
- Every existing test usage passes **no version argument**. That is the whole
  basis of the fix below: an explicit pin and an environment override never
  legitimately appear together, so the collision can simply be refused.
- `omarchy/README.md` documents the installer; the "run the same installer
  manually" section is where the override belongs if it is documented at all.
  Check what it currently says before editing.

## Design (decided; implement exactly this)

Precedence becomes: **an explicit version argument wins; the override applies
only when no version was given.**

```bash
if [[ -n $version && -n ${QUOTAMON_RELEASE_BASE:-} ]]; then
  echo "refusing to install: QUOTAMON_RELEASE_BASE is set but version $version was requested" >&2
  echo "unset QUOTAMON_RELEASE_BASE, or call without a version to use it" >&2
  exit 2
fi
```

Refuse rather than silently prefer one. A user with a stale export who clicks
Update gets a message naming the variable; a test that sets the override and
passes no version is unaffected.

Place this check with the other argument validation, **before** any temp
directory, network call or write — the same position and exit code (2) as the
existing usage errors.

Then simplify the selection so the pin is unmistakable:

```bash
if [[ -n $version ]]; then
  release_base="https://github.com/ubyjvovk/quota_monitor/releases/download/v$version"
else
  release_base=${QUOTAMON_RELEASE_BASE:-https://github.com/ubyjvovk/quota_monitor/releases/latest/download}
fi
```

Add a comment stating why the pin outranks the override: the panel passes the
version it shipped with, and an environment variable must not be able to
redirect a binary that is about to be executed.

`omarchy/README.md`: one sentence in the manual-installer section noting that
passing a version pins the download to that release, and that
`QUOTAMON_RELEASE_BASE` applies only when no version is passed. Do not turn this
into a security essay.

## Out of scope
- **Signing, attestation, or a digest pinned in reviewed code.** This is the
  review's strongest point and it is a separate decision the owner has not made
  yet: it needs a signing key in CI, a public key shipped in the plugin, and a
  verifier dependency beyond the manifest's declared `curl` + `shasum`. Do not
  invent one here. Note also, for whoever picks that up: the checksums do not
  exist until the tag has triggered the build, so a digest cannot simply be
  committed alongside the version bump.
- `QUOTAMON_ARCH` and `QUOTAMON_BIN_DIR`. They select an architecture and an
  install prefix; neither chooses where bytes come from.
- Removing the override entirely. Tests need it, and with this fix it can no
  longer contradict an explicit pin.
- `Panel.qml`. Clearing the variable in the child environment is a plausible
  second layer, but the fix belongs in the script, which is reviewed, testable
  here, and also protects by-hand use. If you think the panel needs a change,
  say so in the report rather than making one.
- The checksum verification, download isolation, and atomic install — all
  correct, leave them alone.
