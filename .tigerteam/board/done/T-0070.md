## Goal
The standalone plugin repository `ubyjvovk/quotamon-omarchy` has **no tags and
no releases**, and its published `manifest.json` still reads
`"id": "quotamon"`, `"version": "1.0.0"` — the pre-CalVer state. Its `master`
is the subtree split of T-0061 (2026-08-31), so everything the CalVer wave
landed under `omarchy/` (T-0067's namespaced id, licence, dependencies block
and About footer; T-0064..T-0069's version plumbing) is unpublished.

The immediate cause is that `scripts/publish-omarchy-plugin.sh` was simply not
re-run. The structural cause is that it is a bare `git subtree split` +
force-push: it pushes no tag, cuts no release, and does not check that what it
is about to publish carries the current `VERSION`. Nothing in the release path
reminds anyone it exists, so a published plugin can silently sit months behind
the manifest version it claims.

Close the structural gap. **Do not publish anything** — see Out of scope.

## Design (decided; implement exactly this)

**1. `scripts/publish-omarchy-plugin.sh`**

- Resolve `ROOT` the way `scripts/build.sh` does and `cd "$ROOT"`, so the script
  works from any directory inside the checkout.
- After the existing branch and clean-tree guards, and before the split, run
  `bash "$ROOT/scripts/check-versions.sh"`. On failure print
  `Refusing to publish: version drift (run scripts/check-versions.sh)` to stderr
  and exit 1. Publishing a manifest that disagrees with `VERSION` is exactly the
  bug this ticket exists to prevent.
- Compute `tag="v$(cat "$ROOT/VERSION")"`.
- Decide whether the tag already exists on the target:
  ```bash
  tag_state=unknown
  if remote_tags=$(GIT_TERMINAL_PROMPT=0 git ls-remote --tags "$target" "refs/tags/$tag" 2>/dev/null); then
    if [[ -n $remote_tags ]]; then tag_state=present; else tag_state=absent; fi
  fi
  ```
  `unknown` (no network, no credentials — the sandboxed lanes have neither) must
  never fail the script: `--dry-run` still exits 0 and reports `unknown`.
- Print, before any push and in `--dry-run` too, exactly these three lines
  followed by the tag line:
  ```
  Omarchy subtree: <sha>
  Publish target: <target> (master)
  Plugin version: <tag>
  ```
  then one of:
  - `Tag <tag>: will be created` (absent)
  - `Tag <tag>: already published — master updated only; bump with scripts/set-version.sh to cut a new plugin release` (present)
  - `Tag <tag>: unknown (could not reach <target>)` (unknown)
- Push behaviour on a real run — master **always**, tag **only when absent**:
  ```bash
  git push "$target" "$split_sha:refs/heads/master" --force
  [[ $tag_state == absent ]] && git push "$target" "$split_sha:refs/tags/$tag"
  ```
  An already-published tag is never moved or deleted: a tag must keep meaning
  the bytes it meant. `unknown` pushes master only and says so.
- `--dry-run` keeps printing `Dry run: nothing pushed` as its last line and
  exits 0 without contacting the remote for anything but the tolerated
  `ls-remote` probe above.
- Keep the existing usage string and argument parsing, including the optional
  positional remote-url override; the new output must work with an overridden
  target too.
- Update the header comment to say the script also tags the plugin repo with the
  current CalVer, which is what triggers the plugin's own release workflow.

**2. `omarchy/.github/workflows/release.yml`** (new file)

- Header comment explaining: this file lives in `quota_monitor` under
  `omarchy/`, reaches the plugin repository through the subtree split, runs only
  there, and is inert in `quota_monitor`.
- `name: release`; `on: push: tags: ["v*"]` plus `workflow_dispatch`;
  `permissions: contents: write`; `runs-on: ubuntu-latest`.
- Steps:
  1. `actions/checkout@v4`.
  2. Verify the tag against the manifest: for a `refs/tags/v*` ref, compare
     `${GITHUB_REF_NAME#v}` with the `version` value in `manifest.json` and exit
     1 on disagreement, with a message naming both. Read it without `jq`
     assumptions — a `grep`/`sed` on the `"version":` line is fine and matches
     how `scripts/check-versions.sh` parses the same file.
  3. Package: `zip -r "quotamon-omarchy-$VERSION.zip"` over the plugin files,
     excluding `.git/*` and `.github/*` — a user unzipping the asset should get
     exactly what `omarchy plugin add` would install.
  4. `softprops/action-gh-release@v2` with the zip in `files:` and
     `generate_release_notes: true`, guarded to tag pushes
     (`if: github.event_name == 'push'`), mirroring the main workflow. A
     `workflow_dispatch` run uploads the zip with `actions/upload-artifact@v4`
     instead, since there is no tag to attach a release to.

**3. Docs**

- `omarchy/README.md`: a short section (or an addition to an existing one)

```yaml
# This workflow lives under omarchy/ in quota_monitor and reaches the plugin
# repository through the subtree split. It runs only from the plugin repository
# root; GitHub treats it as inert in quota_monitor.

name: release

on:
  push:
    tags:
      - "v*"
  workflow_dispatch:

permissions:
  contents: write

jobs:
  release:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Verify tagged version
        run: |
          if [[ "$GITHUB_REF" == refs/tags/v* ]]; then
            tag_version="${GITHUB_REF_NAME#v}"
            manifest_version="$(sed -n 's/^[[:space:]]*"version":[[:space:]]*"\([^"]*\)",[[:space:]]*$/\1/p' manifest.json)"
            if [ "$tag_version" != "$manifest_version" ]; then
              echo "error: tag version $tag_version does not match manifest version $manifest_version" >&2
              exit 1
            fi
          fi

      - name: Package
        run: |
          if [[ "$GITHUB_REF" == refs/tags/v* ]]; then
            VERSION="${GITHUB_REF_NAME#v}"
          else
            VERSION="$(sed -n 's/^[[:space:]]*"version":[[:space:]]*"\([^"]*\)",[[:space:]]*$/\1/p' manifest.json)"
          fi
          zip -r "quotamon-omarchy-$VERSION.zip" . \
            -x '.git/*' '.github/*' 'quotamon-omarchy-*.zip'

      - name: Upload artifact
        if: github.event_name == 'workflow_dispatch'
        uses: actions/upload-artifact@v4
        with:
          name: quotamon-omarchy
          path: quotamon-omarchy-*.zip

      - name: Publish release
        if: github.event_name == 'push'
        uses: softprops/action-gh-release@v2
        with:
          files: quotamon-omarchy-*.zip
          generate_release_notes: true
```
