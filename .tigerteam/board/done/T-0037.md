## Goal
A real account shows `credits 20.00 (not enabled)` while it has **no** credits:
the user configured a $20/month extra-usage cap and the parser prints
`spend.limit − spend.used` as if it were a balance. Read the payload as Claude
means it — `spend.balance` is the prepaid balance, `spend.limit` is the monthly
cap, `spend.used` is this month's spend — and expose balance and spend
separately through the snapshot contract (which already has both fields).

## Context
- Parser: `core/internal/providers/claude/claude.go` → `Snapshot(...)`, the
  `if spend, ok := jsonx.Get(root, "spend")` block. Tests in `claude_test.go`
  (`TestSpendBalanceHonoursEnabledState` and the live-fixture test asserting
  `Balance == "20.00"` encode the wrong reading — rewrite them).
- Real payload (committed, no secrets):
  `QuotaKit/Tests/QuotaKitTests/Fixtures/claude-usage-live.json` → `spend`:
  `used {amount_minor 0, currency USD, exponent 2}`, `limit {amount_minor 2000,…}`,
  `enabled false`, `disabled_reason "out_of_credits"`, `balance null`,
  `cap {money null, credits {amount_minor 2000, exponent 2}}`. Sibling
  `extra_usage {is_enabled false, monthly_limit 2000, used_credits 0.0, …}`
  says the same thing in older vocabulary — ignore it, `spend` is canonical.
- Contract: `snapshot.Credits{HasCredits, Unlimited, Balance *string, Enabled, Spend *string}`
  (`core/internal/snapshot/snapshot.go`). The table renders `balance`/`spend`
  rows from it (`core/cmd/quotamon/table.go` `creditLines`): with `Spend` set,
  a disabled nil/zero balance row is omitted and the spend row still prints —
  exactly the honest rendering for the user's case.
- `jsonx.Get` on a JSON `null` — treat a null value as absent.

## Design — implement exactly this
- `money(obj) (string, bool)`: reads `amount_minor` (number) and `exponent`
  (int, default 2) and `currency` (default "USD"); formats
  `amount_minor / 10^exponent` with `exponent` decimals; prefix `$` when
  currency is USD, otherwise suffix ` <CUR>` (e.g. `12.50 EUR`). Missing or
  null `amount_minor` → not ok.
- From `spend`:
  - `Enabled` = `spend.enabled` (default true when absent).
  - `Balance` = `money(spend.balance)` when ok, else nil.
  - `Spend` = `"<used> of <limit> this month"` when both `money(spend.used)`
    and `money(spend.limit)` are ok; `"<used> this month"` when only used is
    ok; nil otherwise.
  - `HasCredits` = `Enabled && balance amount > 0`.
  - `Unlimited` = false. No `spend` object at all → `Credits == nil` (as now).
- Never derive a balance from `limit − used` anywhere.
- Expected table rows for the live fixture: **no** `credits`/`balance` row,
  and `  spend     $0.00 of $20.00 this month`.
