## Goal
The app's About panel currently shows only the app's own marketing version. The
app has no fetchers of its own — every number it displays comes from the
`quotamon` binary bundled inside `Contents/Resources` — so "which version am I
running" is really two questions. Make About answer both: the app version (which
macOS already fills in from `MARKETING_VERSION`, now CalVer `2026.9.1`) and the
version of the core actually inside this bundle, obtained by running it.

Ask the binary rather than trusting a build-time constant: the bundled core is
copied in by an Xcode pre-build phase and can, in a broken or hand-assembled
bundle, be older than the app around it. Reporting what is really there is the
whole point of the line.

## Context
- `App/AppAbout.swift` is the entire About surface: it activates the app, builds
  an attributed `credits` string (description paragraph + a link to
  `ubyjvovk.github.io`), and calls `NSApp.orderFrontStandardAboutPanel`. The
  standard panel renders `.applicationName` and the bundle's version itself;
  only the `credits` block is ours to compose.
- `App/CoreBinary.swift` exposes `CoreBinary.runner: QuotamonRunner?` — nil when
  the build did not embed the binary — plus `CoreBinary.missingMessage`.
- `QuotaKit/Sources/QuotaKit/Engine/QuotamonRunner.swift` is a struct wrapping
  `run: @Sendable ([String], String?) async throws -> Data`, injectable in
  tests so nothing spawns a process. `snapshot(fresh:)` is the existing
  example of a typed wrapper over `run` — follow its shape exactly, including
  how it maps `ProcessFailure` through `Self.quotaError(for:)`.
- T-0064 added `quotamon --version`, which prints exactly `quotamon <version>`
  and a newline to stdout, e.g. `quotamon 2026.9.1`. An unstamped build prints
  `quotamon dev`.
- `QuotaError` cases in use include `.transport`, `.malformed`, `.notConfigured`.
- Ticket for context, not for editing: `MARKETING_VERSION` is now `2026.9.1`
  in `project.yml`, and `scripts/build.sh` stamps it from the repo-root
  `VERSION` file.

## Design (decided — implement exactly this, do not redesign)
1. `QuotamonRunner` gains:
   ```swift
   /// The version of the `quotamon` this runner executes, as printed by
   /// `quotamon --version`.
   public func coreVersion() async throws -> String
   ```
   - runs `run(["--version"], nil)`;
   - decodes UTF-8, trims whitespace and newlines;
   - strips a leading `quotamon ` prefix when present, so both
     `quotamon 2026.9.1` and a bare `2026.9.1` yield `2026.9.1`;
   - throws `QuotaError.malformed("quotamon reported no version")` when the
     result is empty after trimming;
   - maps process failures exactly the way `snapshot(fresh:)` does (the same
     `do/catch` ladder over `ProcessFailure`, `QuotaError`, and other errors).
2. `AppAbout` resolves the core version before opening the panel:
   - a `private static var cachedCoreVersion: String?` (main-actor isolated)
     so reopening About does not respawn the binary;
   - `show()` stays the menu action's entry point and becomes async internally
     (`Task { @MainActor in … }` or an `async` helper) — activate, resolve, then
     `orderFrontStandardAboutPanel`. The panel must still come to the front.
   - the resolved line is prepended to the existing credits text as its own
     first paragraph, in the same 11pt secondary-label style as the description:
     `quotamon core 2026.9.1`
   - when `CoreBinary.runner` is nil: `quotamon core: not bundled`
   - when the call throws or times out: `quotamon core: unavailable`
   - the description paragraph and the `ubyjvovk.github.io` link stay exactly
     as they are, below the new line.
3. Nothing else changes. In particular, do not add a version row to the quota
   panel, the menu, or the widget.
