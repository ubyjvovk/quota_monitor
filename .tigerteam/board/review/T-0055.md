## Goal
Consolidated findings opus F15, codex F10, codex F9 (see review reports).

## Design — implement exactly this
- `scripts/package.sh` and the workflow's notarize step: write checksums to a
  temp file then `mv` over `SHA256SUMS`, with the glob excluding it
  (`shasum -a 256 $(ls | grep -v '^SHA256SUMS$')` or explicit patterns).
  package.sh also `rm -f "$OUTDIR/SHA256SUMS"` first so a reused outdir is safe.
- `scripts/build.sh`: capture xcodebuild's real status
  (`set -o pipefail` for that pipeline or `PIPESTATUS`), exit non-zero on
  compile failure, and `rm -rf` the expected .app product path before building
  so a stale bundle can never be launched as success.

- `scripts/package.sh` — `rm -f "$OUTDIR/SHA256SUMS"` right after `mkdir -p
  "$OUTDIR"` so a reused outdir starts without a stale checksum file; the
  checksum block now builds an explicit file list (skipping `SHA256SUMS` and any
  leftover directory), refuses to run on an empty outdir, writes to
  `SHA256SUMS.tmp` and `mv`s it into place.
- `scripts/build.sh` — `APP` is defined before the build and `rm -rf "$APP"`
  wipes the previous bundle, so a compile failure can no longer leave a stale
  `.app` for the existence checks (and `open`) to accept as success. The
  xcodebuild pipeline runs under `set +e` and its real status is read from
  `${PIPESTATUS[0]}`; a non-zero status exits with that code and a message
  pointing at the unfiltered log. (`set -o pipefail` was already on at line 9 —
  the bug was the `|| true`, which reported grep's status, not xcodebuild's.)
- `.github/workflows/release.yml` — the notarize step's re-checksum
  (`(cd dist && shasum -a 256 * > SHA256SUMS)`) now removes the old file, hashes
  by explicit pattern (`*.dmg quotamon-*`), and `mv`s a temp file into place.
  Nothing else in the workflow touched.
