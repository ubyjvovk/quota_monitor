## Goal
`quotactl` currently prints, for a Claude Max account:

```
  credits         20.00 remaining
```

That is wrong, and it is the PM's fault rather than a previous worker's — the
T-0003 spec asked for exactly this. The same payload that yields `20.00` also
says `"enabled": false` and `"disabled_reason": "out_of_credits"`. Those credits
are **not spendable**, so "20.00 remaining" tells the user they have headroom
they do not have — the one failure mode this tool exists to prevent.

Teach `Credits` whether the balance is actually usable, set it correctly for
both providers, and render it honestly.

## Context
- `Credits` is in `Models/ProviderSnapshot.swift`:
  `{hasCredits: Bool, unlimited: Bool, balance: String?}`.
- Claude's source data is the `spend` object in
  `Tests/QuotaKitTests/Fixtures/claude-usage-live.json` (already committed, a
  real capture). Relevant keys: `enabled` (Bool), `disabled_reason` (String?),
  `used.amount_minor`, `limit.amount_minor`, `limit.exponent`, `balance`.
- Claude's mapping lives in `Claude.snapshot(...)` in `ClaudeSources.swift`
  (added by T-0003).
- ChatGPT's source data is the `credits` block inside a rollout's `rate_limits`:
  `{"has_credits":false,"unlimited":false,"balance":"0"}`. It is parsed in
  `Codex.snapshot(fromRateLimits:)`. For this account `has_credits` is `false`,
  meaning no purchased credits — that is already correct and needs no change
  beyond carrying the new field.
- Rendering is `ConsoleReport.render` in `Support/ConsoleReport.swift`.

## Design — implement exactly this
1. Add one field to `Credits`, defaulting to `true`:

   ```swift
   /// Whether the balance can actually be spent. A provider can report a
   /// non-zero balance that is switched off (Claude: `spend.enabled == false`
   /// with `disabled_reason`), and showing that as available headroom is the
   /// one thing this tool must never do.
   public var enabled: Bool
   ```
   Keep the existing memberwise `init` working by giving the new parameter a
   default of `true` and placing it **last**.

   **Decoding gotcha — get this right:** `SnapshotStore` persists snapshots to
   disk, so JSON written before this change has no `enabled` key. Implement
   `init(from:)` so the field decodes via
   `decodeIfPresent(Bool.self, forKey: .enabled) ?? true`; a plain synthesised
   `Codable` conformance throws `keyNotFound` on every existing snapshot and
   silently wipes the user's cached reading. Add a test for exactly this.

2. **Claude** — in `Claude.snapshot(...)`, set `enabled` from `spend.enabled`
   (missing key ⇒ `true`). Leave `balance` computed as it is now. Also set
   `hasCredits` to `enabled && remaining > 0` rather than `remaining > 0`.

3. **ChatGPT** — in `Codex.snapshot(fromRateLimits:)`, set
   `enabled = hasCredits || unlimited`, reading those two from the same
   `credits` object already parsed there. A ChatGPT account with no purchased
   credits reports `has_credits: false` and `unlimited: false`, so `enabled`
   becomes `false` — which, combined with a `"0"` balance, means rule 4 below
   omits the line. That is the intended result.

4. **Rendering** — `ConsoleReport.render`'s credits line becomes, in order:
   | condition | line |
   |---|---|
   | `unlimited` | `credits         unlimited` |
   | `enabled`, balance non-nil | `credits         <balance> remaining` |
   | `!enabled`, balance non-nil and non-zero | `credits         <balance> (not enabled)` |
   | `!enabled`, balance nil or `"0"`/`"0.00"` | *(omit the line entirely)* |
   Omitting is deliberate: a zero, switched-off balance is not information, and
   a line that says `0 remaining` reads as a warning about something the user
   never had.
   `renderJSON` gains `"enabled"` alongside the existing credit fields.
