## Goal
`quotactl --live` cannot read the Claude token today. `Keychain.genericPassword`
uses `SecItemCopyMatching`, and for a Keychain item another application created
that call is refused for an unsigned SwiftPM binary — it returns
`errSecInteractionNotAllowed` / `errSecAuthFailed`, so the live Claude source
fails 100% of the time with
`Keychain access to 'Claude Code-credentials' was denied`. When it is *not*
refused outright it can instead raise the system "allow access?" dialog, which
is worse: an interactive prompt in a tool meant to print a number and exit.

The `security` command-line tool reads the same item silently. Verified by the
PM on this machine:

```
$ security find-generic-password -s "Claude Code-credentials" -w
<the JSON blob>          # exit 0, no prompt
```

**Decision (product owner, this session): the `security` CLI is the only path
we use.** No Keychain prompts, ever. The framework strategy stays in the file
as an injectable option so a future signed, entitled app bundle can opt into
it, but nothing selects it by default.

## Context
- File to change: `QuotaKit/Sources/QuotaKit/Support/Keychain.swift` (34 lines).
- The single caller is `ClaudeLiveSource.init`'s default `credentialsProvider`
  in `Providers/ClaudeSources.swift`. **Do not change that file** — this ticket
  keeps `Keychain.genericPassword(service:)` working with its current signature.
- `QuotaError` cases and their meanings are in `Providers/QuotaSource.swift`.
  `QuotaError.reportingPriority` (internal) already ranks failures by how
  actionable they are; reuse it, do not reinvent it.
- Follow the injection convention in AGENTS.md: the seam is a parameter
  default, so tests never touch the real Keychain.

## Design — implement exactly this interface
Invent nothing beyond it; if it cannot be built as specified, stop and use the
BLOCKED protocol rather than improvising a different shape.

```swift
/// One strategy for reading a generic-password item. Injectable so tests
/// never touch the real Keychain.
public struct KeychainLookup: Sendable {
    public let name: String                             // "security" / "SecItem"
    public let read: @Sendable (String) throws -> Data   // service name -> item data
    public init(name: String, read: @escaping @Sendable (String) throws -> Data)
}

public enum Keychain {
    /// The `security` CLI, and only it. `SecItemCopyMatching` is deliberately
    /// not in this list: for an item another app owns it is either refused
    /// outright or answered with an interactive "allow access?" dialog, and a
    /// command-line tool must never block on a GUI prompt.
    public static let defaultLookups: [KeychainLookup] = [.securityCLI]

    /// Shells out to `/usr/bin/security`. The default strategy.
    public static let securityCLI: KeychainLookup

    /// The framework API. Not used by default — see `defaultLookups`. Kept as
    /// an opt-in for a signed app bundle that holds the item's ACL.
    public static let secItem: KeychainLookup   // existing SecItemCopyMatching logic, moved here

    public static func genericPassword(
        service: String,
        lookups: [KeychainLookup] = defaultLookups
    ) throws -> Data
}
```

`genericPassword` semantics:
- Try each lookup in order; return the first success.
- Never invoke a later lookup once an earlier one succeeded.
- If all fail, throw the failure with the **highest `QuotaError.reportingPriority`**,
  ties broken by lookup order (earlier wins). A non-`QuotaError` counts as
  priority 2, matching `HybridProvider.mostActionableMessage`.
- An empty `lookups` array throws `QuotaError.notConfigured`.

(The list-of-strategies shape is kept even though the default has one entry:
it is what makes the whole thing testable without a Keychain, and it is how the
app will opt into `secItem` later.)

`securityCLI` semantics:
- Run `/usr/bin/security` by **absolute path** (never resolve via `PATH`), with
  arguments `["find-generic-password", "-s", service, "-w"]`.
- Read stdout to end **before** `waitUntilExit()` — the blob is ~14 KB and
  reading after waiting can deadlock on a full pipe.
- Trim trailing newline/whitespace from stdout, then UTF-8-encode to `Data`.
- Map the outcome:
  | exit | throw |
  |---|---|
  | 0, non-empty output | *(success)* |
  | 0, empty output | `.malformed("Keychain item '<service>' held no data")` |
  | 44 | `.notConfigured("No Keychain item named '<service>'")` |
  | 51 or 128 | `.unauthorized("Keychain access to '<service>' was denied")` |
  | anything else | `.transport("`security` failed for '<service>' (exit <n>)")` |
- If the process cannot be launched at all, throw `.transport`.
- **Never** write stdout to a log, an error message, or stderr passthrough — it
  is the access token. Error messages may name the service and the exit code
  and nothing else.

## Acceptance criteria
- [ ] `bash .tigerteam/scripts/run-tests.sh` exits 0
- [ ] A test asserts `Keychain.defaultLookups.map(\.name) == ["security"]` —
      that the framework API is not consulted by default is the point of the
      ticket, so it gets its own assertion
- [ ] New tests, all using **injected** `KeychainLookup`s (no real Keychain, no
      `Process`, no network — see AGENTS.md gotcha 3), covering:
      - the first lookup succeeding means the second is never invoked
        (assert with a flag the stub sets)
      - the first failing and the second succeeding returns the second's data
      - all failing throws the most *actionable* error, not merely the last:
        given `[.unauthorized, .notConfigured]` the thrown error is the
        `.unauthorized`; given `[.notConfigured, .unauthorized]` it is still
        the `.unauthorized`
      - an empty `lookups` array throws `.notConfigured`
- [ ] Every new public symbol has a doc comment; the comment on `defaultLookups`
      states *why* the CLI is the only default (refusal + GUI prompt, above)
- [ ] `Keychain.genericPassword(service:)` still compiles for the existing
      caller in `ClaudeSources.swift` with no change to that file
- [ ] No files changed outside `scope`

## Out of scope
- Editing `ClaudeSources.swift`, `main.swift`, or anything under `App/`,
  `Widget/`, or `QuotaKit/Sources/QuotaKit/UI/`.
- Deleting the `secItem` strategy — keep it, just do not default to it.
- Refreshing an expired OAuth token, or writing to the Keychain.
- Any test that shells out to the real `security` binary. It will not work
  under the worker sandbox and will be rejected.
