## Goal
DeepInfra intermittently reports `Could not reach DeepInfra payment endpoint …
context deadline exceeded`. `/payment/usage?from=current` alone takes ~4–5 s
on the reference machine and `LiveSource.Fetch` calls `/payment/config` and
then `/payment/usage` **sequentially** inside the CLI's 10 s overall budget,
alongside four other providers. Twice in three runs it lost the race.

## Context
- `core/internal/providers/deepinfra/sources.go` — `Fetch` → `fetchJSON` ×2.
- The CLI budget (10 s, `cmd/quotamon`) is out of scope; fix the provider.

## Design — implement exactly this
- Issue the two GETs **concurrently** (two goroutines, `sync.WaitGroup` or
  `errgroup`-free channel), each with its own 8 s `context.WithTimeout`
  derived from the caller's ctx. Join; if either failed, return that error
  (Unauthorized beats Transport if both fail).
- If `/payment/config` fails but `/payment/usage` succeeded, still return the
  spend reading with `hasLimit=false` and status `NeedsSetup("Spending limit
  unknown — DeepInfra /payment/config: <err>")` — the spend number is the
  valuable part.
- Wrap a deadline error as `source.Transport("DeepInfra is slow to answer
  (>8 s) — will retry next refresh")` instead of the raw `context deadline
  exceeded` text.

## Acceptance criteria
