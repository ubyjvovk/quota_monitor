## Goal
The root `README.md` still describes a Swift-only macOS app and says ChatGPT
live "returns 404". Since then the core moved to Go (`core/`), ChatGPT live
works via `codex app-server`, Grok and DeepInfra were added, and `quotamon`
is the way a user sees their quotas. Make the docs tell the truth, for a
person who has never seen the repo.

## Context
- Sources of truth (read all; do not contradict them): `GO-PORT.md`
  (design + status table), `PROVIDERS.md` (endpoints/credentials — do NOT
  duplicate its detail, link to it), `core/README.md` (current usage),
  `AGENTS.md` (agent-facing — leave it alone, the PM owns it).
- Run the real thing for the sample output: `cd core && make build &&
  ./bin/quotamon --no-live` (a sandboxed worker may see fewer providers —
  say so with a note if you paste output, or hand-compose a representative
  table with the `—` and `(not enabled)` and `$x.xx this month` cases).

## Design — write exactly this structure

### `README.md` (root) — for users
1. Title + one paragraph: what it is (quota across LLM subscriptions), which
   providers (Claude, ChatGPT/Codex, Grok, DeepInfra; Kimi: no quota API
   yet), which frontends (CLI `quotamon` on macOS/Linux; Waybar module for
   Omarchy/Hyprland; macOS menu-bar app + widget — currently on hold, Swift).
2. **Quick start** — `cd core && make build`, then `./bin/quotamon setup` (show the
   discovery transcript briefly), then `./bin/quotamon`; sample table.
   Mention the config file path and that keys live there with mode 0600.
   Then `quotamon --json`, `quotamon waybar`, `quotamon check` one line each.
   Cross-compile: `make matrix`.
3. **Omarchy / Waybar** — the config snippet, class names for CSS, note
   about `interval`.
4. **Where the numbers come from** — a compact table: provider · credential
   (one phrase) · route · status (✅ live / cached / ❌). Link PROVIDERS.md
   for detail. Keep the two paragraphs that explain *local vs live* and why
   stale readings show `—`.
5. **Principles** — keep the existing "Design notes" bullets that are still
   true (absence is never zero; credentials by path; stale readings
   corrected; honest identification). Drop the "ChatGPT live 404" text and
   the `QUOTA_MONITOR_CODEX_USAGE_URL`-as-workaround framing (it is now an
   optional HTTP route). Keep the chart/sparkline rationale but mark it as the
   macOS app's design (on hold).
6. **macOS app & widget** — one short section: on hold; build instructions
   as today; the plan is that the app runs the bundled `quotamon` and the
   widget reads the snapshot (link GO-PORT.md "Platform landings").
7. **Layout** — update the tree: `core/` first, then `QuotaKit/`, `App/`,
   `Widget/`, `scripts/`.
8. **Troubleshooting** — `quotamon check` output explained (kinds:
   notConfigured / unauthorized / transport / malformed / noDataFound and
   what to do for each); the Keychain prompt note (we use the `security`
   CLI, never the framework API); "ChatGPT reports usage only after a Codex
   turn".
9. **Contributing / for agents** — two lines pointing at `AGENTS.md`,
   `PROVIDERS.md`, `GO-PORT.md`.

### `core/README.md` — for users of the binary
Keep it; update Usage so the bare `quotamon` table comes first with the
sample, then `--json`, `snapshot`, `waybar`, `check`; add Grok and DeepInfra
provider subsections (from their in-package READMEs; DeepInfra: spend, not
quota); environment variables section (`QUOTA_MONITOR_DIR`,
`QUOTA_MONITOR_CODEX_USAGE_URL`, `DEEPINFRA_KEY`); exit codes.

Style: short sentences, no marketing, headings a reader can scan. Every
command in a fenced block. Prefer tables over prose for provider facts.
