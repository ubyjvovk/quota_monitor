## Goal
Three consolidated cache-policy defects (opus F7, ds F1/F2/F8, ds F7 in
`.tigerteam/reviews/2026-08-31-*.md` — read them first): the cache is only
consulted when a token is stale, so live-only providers (Grok/DeepInfra/Kimi)
drop to `Unavailable` on a plain outage while a seconds-old reading sits on
disk; the stale-token gate serves a cache up to `ShortestWindow` old (5h Kimi,
7d Grok) without ever attempting live; and `fallbackReading` overwrites a
provider's own actionable status with a generic reset message.

## Design — implement exactly this
- `PreFetch` loads the cached reading unconditionally (cheap disk read) into
  `cachedOutcome`; the EARLY-SERVE short-circuit (skip live entirely) now
  requires: token stale AND cache age < 15 minutes. Otherwise proceed to
  refresh + live as today.
- `Fetch` fallback chain on live failure (after local): use the cached reading
  whenever it exists and its windows/credits are usable, labelled with its age
  and `origin: local`-equivalent (the existing `fallbackReading` labelling),
  status explaining the live failure — before ever returning `Unavailable`.
- `fallbackReading`: when the source already attached a `needsSetup` status,
  keep it; apply the generic "window has since reset" message only when the
  source reported `ok` (ds F7).
- Table-driven tests: outage+valid-token+cache → cached served with age
  label; stale token + 3h cache → live attempted (not early-served); stale
  token + 10min cache → early-served; provider status preserved.
