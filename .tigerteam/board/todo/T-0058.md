## Goal
The product owner is dropping semantic versioning: versions are now
`{major}.{commit count on master}` (e.g. `0.264`). The release workflow needs
NO change (it already strips `v` from any tag and uses the rest verbatim);
what is missing is a way to compute and cut such a tag, and local builds
stamping the same shape.

## Context
- `.github/workflows/release.yml`: `push: tags: v*` → `VERSION=${GITHUB_REF_NAME#v}`
  → `MARKETING_VERSION="$VERSION"`. Works for `v0.264` as-is — do not touch it.
- `scripts/build.sh` builds Debug locally; `project.yml` pins
  `MARKETING_VERSION: 0.1.0` (leave project.yml alone — override on the
  xcodebuild command line).
- Current release is `v0.2.0`; commit counts are already well above 2, so the
  next computed tag sorts after it numerically and no migration is needed.

## Design — implement exactly this
### `scripts/release.sh` (new, executable)
- `MAJOR=0` at the top with a comment: bumped by hand on breaking rewrites;
  the minor is `git rev-list --count HEAD`.
- Refuses (message, exit 1) when: not on master, working tree dirty, or the
  computed tag already exists.
- Computes `TAG="v${MAJOR}.$(git rev-list --count HEAD)"`, prints what it will
  do, tags annotated (`git tag -a "$TAG" -m "Quota Monitor ${TAG#v}"`), pushes
  `git push origin master "$TAG"`, prints the Actions URL hint.
- `--dry-run` prints the tag and exits 0 without tagging.

### `scripts/build.sh`
- Compute `VERSION="${MAJOR_DOT_COUNT}"` the same way (duplicate the two
  lines; a shared lib file is overkill) and pass
  `MARKETING_VERSION="$VERSION"` on the xcodebuild invocation, so the About
  box of a local build shows the real commit-count version instead of 0.1.0.

### `README.md`
- The Releases bullet in `## Contributing / for agents` now says: cut a
  release with `scripts/release.sh` (version = `{major}.{commit count}`,
  major bumped by hand); tags still trigger `.github/workflows/release.yml`.

## Acceptance criteria
