## Goal
Installing the Omarchy plugin currently needs a clone + copy + a separately
obtained binary. Target flow: `omarchy plugin add
https://github.com/ubyjvovk/quotamon-omarchy` (a plugin-only repo published
from `omarchy/` here), then ONE click in the panel installs the binary and
bootstraps the config. No `curl | bash`, ever: the fetch script ships inside
the plugin the user already chose to trust, runs only on explicit action, and
verifies checksums.

## Context
- `omarchy/` is the plugin source of truth (manifest.json already at its
  root, so a subtree of this prefix IS a valid plugin repo). Panel process
  handling: `omarchy/Panel.qml` (argv Process + watchdog, T-0040/T-0056).
- Releases carry `quotamon-linux-{amd64,arm64}` and `SHA256SUMS`
  (`https://github.com/ubyjvovk/quota_monitor/releases/latest/download/<name>`).
- The plugin repo does not exist yet (owner will create it); nothing you do
  pushes anywhere — the publish script only pushes when the OWNER runs it.
- You cannot run Omarchy/QML; both scripts must be offline-testable and
  tested via the env seams below. `node`, `bash`, `git`, `curl`, `shasum`
  are available.

## Design — implement exactly this
### `omarchy/fetch-quotamon.sh` (new, executable, ~60 lines, heavily commented)
- Purpose line up top: installs/updates the `quotamon` binary from the main
  repo's GitHub release and bootstraps the config; run by the panel's Install
  button or by hand; never runs unattended.
- Env seams (each defaulted): `QUOTAMON_RELEASE_BASE` (default the
  releases/latest/download URL above; tests use a `file://` dir),
  `QUOTAMON_ARCH` (default from `uname -m`: x86_64→amd64, aarch64|arm64→arm64,
  else exit 1 with message), `QUOTAMON_BIN_DIR` (default `$HOME/.local/bin`).
- Steps: download `quotamon-linux-$ARCH` and `SHA256SUMS` to a mktemp dir
  (curl -fsSL); grep the binary's line out of SHA256SUMS and verify with
  `shasum -a 256 -c` (mismatch or missing line → abort, nothing installed);
  install atomically (`mv` into `$QUOTAMON_BIN_DIR/quotamon`, `chmod +x`,
  mkdir -p first); if `"$BIN" providers` exits 3 (no config), run
  `"$BIN" setup --yes` and print the DeepInfra hint
  (`quotamon config set deepinfra --api-key-stdin`); print where it installed
  and whether PATH covers it.
- Idempotent: re-running replaces the binary only after a fresh checksum pass.

### `omarchy/Panel.qml` — Install button
- In the empty state (`rows.length === 0`), below the existing text, a
  `Button` "Install quotamon" (reuse the Refresh button's component/styling):
  runs the plugin's own script via a second Process
  (`installProc.command = ["bash", <plugin dir>/fetch-quotamon.sh]` — derive
  the path from this file's location, e.g. strip `file://` off
  `Qt.resolvedUrl("fetch-quotamon.sh")`; document the mechanism). Yes, argv
  bash with a FIXED literal path is fine — nothing user-controlled is
  interpolated.
- While running: button disabled, label "Installing…"; buffer stdout+stderr;
  on exit 0 → `refreshNow(true)`; non-zero → tail of output into `lastError`.
  Reuse the watchdog pattern with a longer bound (120 s, downloads).
- `omarchy/README.md`: install section becomes the 3-step flow (plugin add →
  click icon → Install button), with the manual script invocation and the
  by-hand path as fallback; note the checksum verification.

### `scripts/publish-omarchy-plugin.sh` (new, executable)
- Publishes `omarchy/` as the plugin repo: refuses on uncommitted TRACKED
  changes (`--untracked-files=no`, per release.sh) or off-master; builds
  `git subtree split --prefix=omarchy HEAD`; pushes the resulting commit to
  `$1` (remote URL, default `git@github.com:ubyjvovk/quotamon-omarchy.git`)
  branch `master` with `--force-with-lease`-equivalent for subtree
  (`git push <url> <sha>:refs/heads/master --force`); `--dry-run` prints the
  split sha + target and pushes nothing. Comment: history is generated from
  quota_monitor; the plugin repo is a publish target, PRs happen upstream.
- `README.md` (root): Omarchy section rewritten to the new flow; the
  clone+copy block demoted to "developing the plugin"; one line for
  maintainers about publish-omarchy-plugin.sh.
