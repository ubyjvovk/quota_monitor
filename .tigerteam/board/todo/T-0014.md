## Goal
`runAppServer` in `core/internal/providers/codex/app_server.go` closes stdin
right after writing the three requests. On this machine `codex app-server`
then exits before answering `id: 2`, so the live route always fails with
"returned no id:2 rate-limits reply" and the CLI silently falls back to the
rollout tail. Verified by the PM:

```
printf '%s\n' <3 lines> | codex app-server --stdio            # → id:1 + notification only
{ printf '%s\n' <3 lines>; sleep 5; } | codex app-server --stdio   # → …, then the id:2 reply
```

Fix the default runner; the parser and the injected-`Run` seam stay as they are.

## Context
- `PROVIDERS.md` § ChatGPT / Codex now states the corrected protocol (the
  earlier "close stdin after writing" sentence was wrong — the ticket that
  shipped this code followed the doc faithfully; no blame).
- The `Run` seam is `func(ctx, requests []byte) ([]byte, error)`; keep its
  signature. Only `runAppServer` changes.

## Design — implement exactly this
In `runAppServer`: start the process with stdin/stdout pipes; write the
requests; **do not close stdin yet**; read stdout with a `bufio.Scanner`
(1 MiB buffer) line by line, appending every line to the returned buffer;
stop as soon as a line parses as JSON with `"id": 2` (use `jsonx`); then
close stdin, and `Wait` — if the process has not exited within 1 s, kill it
(a kill after we already have the reply is not an error). If stdout hits EOF
before an id:2 line, close stdin, `Wait`, and return whatever was read (the
existing parser then reports Malformed). Context cancellation (the caller's
10 s timeout) must kill the process via `exec.CommandContext` as today.

Add a test for the runner using a fake `codex` script: create a temp dir with
an executable `codex` shell script that prints the id:1 line, reads the
three request lines from stdin, prints the id:2 line (copy it from the
fixture), and then blocks on stdin until EOF (`cat >/dev/null`) before
exiting — i.e. it behaves like the real server: the reply comes while stdin
is still open, and the process only exits once stdin closes. Put that dir first on `PATH` via
`t.Setenv("PATH", …)` and call `runAppServer` (unexported — same package
test). Assert the id:2 line is in the output and the call returns within 3 s.
Skip the test on Windows.
