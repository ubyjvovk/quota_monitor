## Goal
`Claude.windows(from:)` looks for three hard-coded top-level keys —
`five_hour`, `seven_day`, `seven_day_opus`. The PM captured a real response
from `GET https://api.anthropic.com/api/oauth/usage` (saved verbatim as the
fixture in `scope`) and that shape has moved on:

- `seven_day_opus` is `null`; so are `seven_day_sonnet`, `seven_day_cowork`
  and a dozen other buckets. The hard-coded "Opus wk" window is dead.
- The response carries a canonical, **self-describing `limits` array** —
  each entry has `kind`, `group`, `percent`, `severity`, `resets_at`,
  `is_active`, and an optional `scope.model.display_name`.
- That array contains a `weekly_scoped` entry at **20%** scoped to a model,
  `is_active: true` — the most constrained limit on the account. The current
  code reports 14% as the worst weekly figure and **never shows the 20% at
  all**. That is the bug: the tool under-reports how close the user is to
  their limit, which is the one thing it exists to get right.

Parse `limits` as the primary source, keeping the top-level keys as a
fallback for responses that lack it.

## Context
- Fixture (already committed, real shape, no credentials in it):
  `QuotaKit/Tests/QuotaKitTests/Fixtures/claude-usage-live.json`.
  Load it with `Bundle.module` like the existing fixture helpers do.
- **The response has no `rate_limits` wrapper** — windows sit at the top
  level. `ClaudeLiveSource.fetch` already handles this via
  `root.firstValue(forKey: "rate_limits") ?? root`; leave that alone.
- The percentage key here is `utilization` (already in the `forAnyKey` list);
  in the `limits` array it is `percent`.
- `ClaudeLocalSource` reads the statusline mirror, which uses the older
  `rate_limits` + `used_percentage` shape. **It must keep working unchanged** —
  its fixture is `claude-mirror.json` and the test
  `claudeMirrorParsesBothWindows` must still pass untouched.
- `QuotaWindow` is `{id, label, kind (.session/.weekly), usedPercent, resetsAt,
  windowMinutes}`. `ProviderSnapshot.credits` exists and is currently only
  populated by the Codex source.

## Design — implement exactly this
Add to `enum Claude`:

```swift
/// Builds windows from the `limits` array — the endpoint's canonical,
/// self-describing list. Returns nil when the document has no usable array,
/// so the caller can fall back to the legacy top-level keys.
static func windowsFromLimits(_ root: JSONValue) -> [QuotaWindow]?
```

Mapping, per entry in `limits`:
- `id` — the entry's `kind` (`session`, `weekly_all`, `weekly_scoped`).
- `label` — `"5h"` for `group == "session"`; `"Week"` for `weekly_all`;
  for `weekly_scoped`, the model display name when present
  (`scope.model.display_name` → `"Fable wk"`), else `"Week (scoped)"`.
- `kind` — `.session` when `group == "session"`, else `.weekly`.
- `windowMinutes` — `300` for session, `60 * 24 * 7` for weekly.
- `usedPercent` — `percent`; `resetsAt` — `resets_at`.
- **Skip** entries whose `percent` is missing or null.
- Preserve the order the array gives.

`Claude.windows(from:)` becomes: `windowsFromLimits(root) ?? <existing
per-key logic>`. Return the legacy path whenever `limits` is absent, not an
array, or yields no usable entries — so the mirror keeps working.

Also map `spend` → `ProviderSnapshot.credits` in `Claude.snapshot(...)`:
- `balance` — remaining credits as a display string derived from
  `limit.amount_minor - used.amount_minor` scaled by `exponent`
  (`2000` minor with exponent `2` → `"20.00"`), `nil` if either side is absent.
- `unlimited` — `false`.
- When `spend` is absent, `credits` stays `nil`.

**Do not surface the codenamed buckets** (`tangelo`, `iguana_necktie`,
`nimbus_quill`, `omelette_promotional`, `cinder_cove`, `amber_ladder`,
`juniper_tide`). They are unreleased server-side experiments, several report
`0.0` utilization, and showing them as real quota would be wrong. The
`limits`-array path excludes them for free; make sure the fallback path does
too by keeping its explicit `knownWindows` allowlist.
