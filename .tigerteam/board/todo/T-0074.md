## Goal
Two cleanups that belong together, both consequences of the Go core having won.

**1. `GO-PORT.md` goes.** It is the plan and status board for a port that
finished. The owner's call, stated directly: *"do delete the GO-PORT.md, it
serves no purpose anymore - we've progressed way too far."* Delete the file and
every live pointer to it.

**2. `quotactl` is gone** (T-0073 deleted it), but two places still send a
reader — or a user's shell — to it. One of them actually breaks.

## Context
- `scripts/install-claude-statusline.sh:48` prints:
  `echo "Open a Claude Code session, then re-run: swift run quotactl"`
  After T-0073 that command errors out. This is the one that breaks a real
  user, so treat it as the sharp end of the ticket. The replacement is the Go
  binary, `quotamon` — read `scripts/claude-statusline-mirror.sh` and the rest
  of `install-claude-statusline.sh` before choosing the wording, and make the
  printed command one the user can paste and run.
- `README.md:260` lists `Sources/quotactl/  diagnostic CLI (the parity
  reference)` in the Layout section — a directory that no longer exists.
- `README.md:312` links `[GO-PORT.md](GO-PORT.md) — the design record and
  status of the Go core port.` That link must go with the file.
- Delete the file with `git rm GO-PORT.md` so the removal is staged as a
  deletion, not left as an untracked stray.
- **`AGENTS.md` also references it twice (lines 14 and 62). Do not touch
  `AGENTS.md`** — it is the PM's file and the PM updates it when accepting this
  ticket. Note in your report that those two references are still live so the
  PM cannot miss them.
- Ticket files under `.tigerteam/board/` and entries in `.tigerteam/STATE.md`
  mention `GO-PORT.md` constantly. Those are a historical record of work as it
  happened and are **not** references to fix. Leave every one of them alone.
- `TIGERTEAM-BUILD-NOTES.md` at the repo root is untracked and not yours. Leave
  it alone.
