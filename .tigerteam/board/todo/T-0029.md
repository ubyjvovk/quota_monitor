## Goal
The macOS app (and any GUI) must run first-run setup without a terminal. Give
the core machine-readable commands so a GUI can list providers, read config,
and write config through the core (keeping 0600 + validation in one place).
The interactive `quotamon setup` wizard stays as-is for terminal users.

## Context
- `core/internal/discover/discover.go` — `All() []Finding` already exists
  (Found, Supported, Detail, Hint, NeedsKey, ID, DisplayName). Add JSON output.
- `core/internal/config/config.go` — `Config`, `Provider{Enabled, Live, APIKey}`,
  `Load()` (ErrMissing when absent), `Save()` (atomic, 0600), `Default()`,
  `Path()`. Reuse; do not change the on-disk shape.
- CLI dispatch + flag parsing in `core/cmd/quotamon/main.go`; `setup`/`providers`
  already bypass the mandatory-config gate — the new commands must bypass it too
  (they exist to create/inspect config).

## Design — implement exactly this
New subcommands (each bypasses the config-missing gate; none hits the network):
- `quotamon discover --json` → the `discover.All()` findings as a JSON array,
  keys `id, displayName, found, supported, detail, hint, needsKey`, in
  registry order. Without `--json`, keep/print the existing human table
  (reuse `providers`' renderer or discover's table; do not require a config).
- `quotamon config path` → prints `config.Path()` and a newline; exit 0.
- `quotamon config get [--json]` → `--json` prints the effective config
  (Default() merged with the file when present) as JSON with sorted keys;
  without `--json`, a short `id: on|off (detail)` table. Missing file is not
  an error here — print the defaults and exit 0.
- `quotamon config set <provider> [--enabled=<bool>] [--api-key=<v>] [--live=<mode>]`
  → load (or Default() when ErrMissing), apply only the flags given to that
  provider's entry (creating it), then `Save()`. Unknown provider id → error
  to stderr, exit 2. `--live` only valid for `codex` (values app-server|http|off)
  → else exit 2. At least one flag required → else exit 2. On success print
  `wrote <path>` and exit 0. Never echo the api-key value back.
- Unknown `config` subcommand or bad flag → usage on stderr, exit 2.

Add a `MarshalableFinding`/JSON tags on `discover.Finding` (or a small DTO in
the command) — do not leak internal-only fields. Keep `discover.All` local-only.

## Acceptance criteria
- [ ] `bash .tigerteam/scripts/run-tests.sh` exits 0
- [ ] `discover --json` test (temp `$HOME`, stubbed security runner): valid JSON array, one object per provider in registry order, every documented key present, no network/subprocess beyond the injected probes
- [ ] `config path` prints `config.Path()` honouring `QUOTA_MONITOR_DIR`
- [ ] `config get --json` on a temp dir with no file prints the defaults (all providers, enabled=false) and exit 0; with a file, prints its merged content; output parses as JSON with sorted keys
- [ ] `config set deepinfra --enabled=true --api-key=SECRET` writes a 0600 file with that entry; a second `config set claude --enabled=true` preserves the deepinfra entry (load-modify-save); stdout never contains `SECRET`
- [ ] `config set codex --live=bogus` → exit 2; `config set nosuch --enabled=true` → exit 2; `config set claude` (no flags) → exit 2
- [ ] `core/README.md` Configuration section documents the four commands (add to scope in the report)
- [ ] No files changed outside scope (+ `core/README.md`)

## Out of scope
The interactive wizard (unchanged), the Swift app, networking, editing the
config on-disk schema.
